### 1. Information We Collect and Process

Backtrace collects only the information necessary to authenticate users, fulfill repository architecture analysis, manage subscription quotas, and maintain system reliability.

#### A. User Identity & Account Information (GitHub OAuth)
When authenticating via GitHub OAuth 2.0, we collect and store:
- **GitHub User ID** (`github_id`): Unique identifier from GitHub.
- **GitHub Username** (`github_username`): Your public GitHub handle.
- **Email Address** (`email`): Primary email address associated with your GitHub profile (if shared).
- **Avatar URL** (`avatar_url`): URL to your public GitHub profile image.
- **Administrative Status** (`is_admin`): System role flag for account access control.

*Note: We do not collect or store your GitHub account password.*

#### B. Repository Source Code & Analysis Data
When you submit a software repository for analysis:
- **Repository Metadata:** Repository URL, default branch name, commit SHAs, file paths, file sizes, and commit timestamps.
- **Source Code Files:** Source code files parsed to construct Abstract Syntax Trees (AST), dependency import graphs, domain segmentation clusters, and architectural sequences.
- **Derived Analysis Results:** Generated build sequences, dependency tiers, milestone summaries, and structural diagrams stored in our persistence database (`backtrace.db`).

#### C. Billing & Payment Information
- **Stripe Customer Identifier** (`stripe_customer_id`): Opaque identifier generated by Stripe.
- **Stripe Subscription Identifier** (`stripe_subscription_id`): Identifier tracking active subscription plan status.
- **Usage Metrics** (`usage_count`): Monthly counter tracking analyzed repository volume against subscription tier limits.
- *Payment Processing Exclusion:* All credit card numbers, billing addresses, CVV codes, and bank details are processed directly and securely by Stripe, Inc. Backtrace servers never touch or store raw payment card data.

#### D. Telemetry, Analytics & Error Diagnostics
- **Product Telemetry (PostHog):** We capture strictly bounded product interaction events (`user_signup`, `analysis_started`, `analysis_completed`, `tier_upgraded`). Event properties are limited to operational metrics (e.g., total files analyzed, execution duration, domain counts). Sensitive codebase contents and user code strings are excluded from telemetry payloads.
- **Error Monitoring (Sentry):** Application exceptions and crash reports are transmitted to Sentry. In accordance with our security filters (`sentry.py`), all incoming payloads are sanitized before transmission:
  - Authorization headers (`Bearer` tokens) are stripped.
  - HTTP cookies (session tokens, refresh tokens) are redacted.
  - Sensitive parameters (passwords, private keys, API secrets) are scrubbed.

### 3. Data Retention, Caching & Automatic Deletion

Backtrace maintains strict data minimization and retention policies:

1. **30-Day Analysis Cache Expiration:**
   - Detailed repository analysis records, segmented AST nodes, and sequence graphs are retained in the application database for a default Time-To-Live (TTL) of **30 days**.
   - Expired records are automatically pruned by background cache sweep routines (`StorageRepository.clean_expired_records`).
2. **In-Flight Repository Workspaces:**
   - Temporary repository clones and in-memory AST representations created during analysis are purged from disk immediately upon pipeline completion or error termination.
3. **Database Backups:**
   - Regular snapshot backups of the operational database (`/data/backtrace.db`) are created for disaster recovery and system integrity. Backup archives adhere to encrypted storage standards and are cycled on a rolling retention schedule.

### 4. User Rights, Data Erasure & Consent Revocation

You retain full control over your personal data:
- **Right to Erasure (Account Deletion):** You may request the permanent deletion of your account, user profile, and all associated analysis histories by contacting support or initiating an account purge.
- **Session Revocation:** Logging out via `/auth/logout` immediately revokes active refresh tokens and clears authentication cookies across your client sessions.
- **Repository Access Revocation:** You may revoke Backtrace's OAuth permissions at any time via your GitHub account settings (`github.com/settings/applications`).

---

### 5. Security Safeguards

Backtrace implements multi-layered security controls to protect your code and data:
- **Unprivileged Container Execution:** Production workloads run strictly under non-root users (`UID 10001 / appuser`) with locked file-system permissions.
- **Fail-Fast Secrets Architecture:** All API secrets and keys are isolated via strict environment validation with zero development fallbacks.
- **Automated Secret Redaction:** Code ingestion routines detect and redact sensitive credentials before persistence or synthesis.
