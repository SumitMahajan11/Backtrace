# Open Questions / Deferred Items

These were intentionally deferred during planning — not forgotten, just not urgent enough to block the start of building. Revisit each before it becomes relevant.

### Before public launch
- **Security / Production Egress Proxy**: While application-level DNS IP pinning (`--add-host=github.com:<validated_ip>`) and `-c http.followRedirects=false` eliminate DNS rebinding TOCTOU and HTTP redirect attacks during Phase 1 clone, production deployment will additionally enforce container egress filtering via an outbound forwarding proxy or iptables rules restricted strictly to GitHub's published CIDR ranges (AS36459).
- **Legal/ToS wording**: underlying safe behavior (secret redaction, deletion mechanism) is built in already; the actual written terms-of-service/privacy-policy documents still need to be drafted and reviewed (consider real legal review given user-uploaded code + consent-based data use).
- **Billing tier specifics**: exact numbers — how many free analyses/month, what repo size triggers the paywall, whether any features (e.g., sequence-reasoning) are paid-only from the start or universal.
- **Content moderation escalation**: what actually happens once a report comes in — who reviews it, how fast, what the takedown process looks like.

### Nice-to-haves, not blockers
- **Untested Integration Point — Live Gemini Embeddings API Verification (`models/text-embedding-004`)**: Verified ZERO live executions to date. All automated tests and evaluations ran exclusively against the offline deterministic 128-dim n-gram feature hash embedder fallback because `GEMINI_API_KEY` was not exported in the environment. Authentication handling, rate-limit behavior, quota management, and real response-format parsing currently have **zero live runtime verification** (code-review-level confidence only). Run `python -m scripts.smoke_test_gemini_embeddings` as a pre-flight smoke test before deploying to production with live credentials.
- **[RESOLVED] Systems Library Domain Taxonomy (`CORE` Category on FULL 2,750-File Dataset)**: Re-evaluated Layer 4 domain categorization across the complete, un-sampled 2,750-file dataset of all 7 benchmark repos (`tokio-rs/tokio`: 874, `tlaplus/Examples`: 1019, `fmtlib/fmt`: 145, `pallets/flask`: 236, `expressjs/express`: 214, `spring-petclinic`: 132, `gin-gonic/gin`: 130). Uncategorized rate dropped from **53.0% → 0.2%** on `tokio` (503 files categorized as `CORE`), from **43.0% → 21.6%** on `tlaplus` (429 files categorized as `CORE`), and from **35.0% → 12.4%** on `fmt` (24 files categorized as `CORE`). Web application classifications across `flask`, `express`, `gin`, and `spring-petclinic` remained unaffected.
- **[VERIFIED] Layer 1 End-to-End Pipeline Integration Status**: Confirmed that prior Stage 2 and Stage 3 layer evaluations intentionally bypassed Layer 1's `IngestionService` because 4 of the 7 benchmark repos (`tokio`: 874, `tlaplus`: 1019, `flask`: 236, `express`: 214) exceed `IngestionService`'s strict `MAX_REPO_FILE_LIMIT_V1 = 150` file cap (which intentionally raises `IngestionLimitExceededError`). Verified end-to-end integration (Layer 1 Ingestion → Layer 2 AST Parsing → Layer 4 Segmentation → Layer 5 Hybrid RAG) on a real repository within the 150-file cap (`gin-gonic/gin`, 121 files) via `scripts/test_end_to_end_pipeline.py`.
- **Python AST Import Basename Collision Scope (Same-Package vs Cross-Package Ambiguity)**: The AST resolver patch prioritizes same-directory relative paths (`source_dir / rel_path`) first and sorts the global basename fallback list (`sorted(all_repo_files)`). This is proven correct for intra-package duplicate basename collisions (e.g. `src/flask/app.py` vs `tests/test_apps/cliapp/app.py`). However, for arbitrary cross-package duplicate basename collisions in new repositories where neither file is in the importing file's directory, the `sorted()` fallback guarantees determinism (identical resolution across all hash seeds), but remains a heuristic tie-break rather than semantically verified resolution. Revisit with package-hierarchy namespace tracking if cross-package duplicate basenames cause mis-resolutions in multi-package monoliths.
- **Public API**: whether to eventually expose the pipeline as an API for other developers to build on. Backend is already being built API-first, so this is a config/access decision, not an architecture change, when the time comes.
- **Email notifications**: currently in-app only for v1; revisit once there's a real reason users need to leave the page mid-analysis (e.g., very large repos take too long to wait around for).
- **C++ parsing & build-system awareness**: `libclang` Python bindings confirmed and implemented for structural AST and include parsing. Full build-system-aware parsing (reading `CMakeLists.txt` or `compile_commands.json` for precise include paths and macro defines) is deferred as a future enhancement.
- **TLA+ parsing depth**: currently planned as "detect presence only," not full parsing, given how rare and structurally different it is from the other 8 languages. Revisit if it turns out to matter more than expected.
